# Assistant Dock

- Agent-neutral surface. Codex is the only implemented backend today. The dock keeps its accessible "Assistant" label; concrete agent/provider/model details live in the project switcher, not an always-visible status row.
- State and streaming live in `../../context/useCodexAssistant.ts`; the dock renders only.
- Keep the top to two compact rows: project-name switcher with header actions, then conversation tabs. Full paths and provider/model metadata appear only in the closed-by-default switcher or its tooltip. Do not add extra path/status/project-list rows above the conversation.
- `AssistantProjects.tsx` lists assistant working folders in a native details dropdown, dismissible by Escape or outside click/focus. Selecting a folder closes it and restores switcher focus. Add folder uses the existing read-only `/api/dirs` browser in a native dialog and restores switcher focus when closed. The workspace is pinned as the default project. Folder selection never calls `setWorkspaceDir`; tabs and history follow the selected project. No external chat-history import/sync.
- Assistant replies render through `../runtime/MarkdownPreview`. All streaming messages and SDK activities share one native details timeline in transcript order, open initially. Completion collapses it and moves only the last message outside as the final answer. Failed/stopped turns keep all messages in their timeline; legacy turns use their last message as the answer without changing storage. Intermediate prose renders directly; borderless activity rows expand inside it. Commands expand into a scrollable shell panel with the unwrapped command (`shellCommand` strips the `bash -lc '…'` wrapper the SDK reports; the CLI hides it the same way), unmodified output, and actual status (never infer success from missing status). Duration comes from the prompt's `durationMs`; legacy turns use “View steps”.
- Research-context chips remain reference-only. Image attachments use paste, file selection, or drop: PNG/JPEG/WebP, up to four per message, 5 MiB each. Upload through the local `/api/assistant/images` endpoint; pass validated image references to `send`. Reset/abort drafts on session/project changes. Sent-image thumbnails use persistent server URLs; do not store base64 in browser history.
- Command row summaries omit recognized shell wrappers and truncate long commands. Preserve the original command in stored history, the tooltip, and the expanded shell panel. Checks: `node src/components/assistant/command.test.mjs`, `node src/components/assistant/workspaceSync.test.mjs` (supports `PLAYWRIGHT_CHROMIUM_EXECUTABLE`; mocks model and vault traffic).
- Questions and final responses have copy controls; fenced blocks share `../runtime/CopyButton`. Edit restores a question and its image references to the composer, confirms replacement of a nonempty draft, and sends as a new turn without rewriting saved history.
- `assistant.css` maps the panel's own font-size preference; use it instead of hardcoding sizes so the setting scales the whole dock.
- Typography uses local system sans for prose and controls; reserve monospace for workspace paths, code, and expanded activity output.
- Header tabs show only open conversations; their X closes the tab and keeps the saved history. Deleting a conversation lives solely in the history modal and is confirmed. Tabs support arrow/Home/End navigation, and switching/closing/deleting stay disabled during streaming.
- The header history button opens a native modal listing every saved conversation with search, open, and delete. Keep native Escape dismissal, focus trapping, and focus restoration.
- Checks: `npm run lint`, `npm run build`, `node --test src/context/sessions.test.mjs`, `node src/components/assistant/assistant.test.mjs` (optional `PLAYWRIGHT_CHROMIUM_EXECUTABLE` for a system browser). The UI check starts an isolated Vite server and mocks vault/model traffic; it does not change the user's vault or make paid model calls.
